# Report Contract

输出契约，确保报告一致性和质量。

## 核心原则

1. **结论在前**：先给结论，再展示推理
2. **用户友好**：概念术语后紧跟实用翻译
3. **事实标记**：明确区分 observed/estimated/assumed
4. **行动导向**：每个行动必须说明改变什么

---

## 必选章节

### 1. 先看结论

**章节 ID**: `conclusion`

**用户友好标题**: `先看结论`

**必含内容**：
- 最该先解决什么
- 为什么是它
- 置信度（高/中/低）
- 第一个行动

**输出模板**：
```markdown
## 先看结论

**最该先解决**：[核心问题]

**为什么是它**：[核心理由，2-3 点]

**置信度**：高/中/低

**第一个行动**：[具体行动，含负责人和期限]
```

---

### 2. 先把现状说清楚

**章节 ID**: `current_state`

**用户友好标题**: `先把现状说清楚`

**必含内容**：
- 目标
- 阶段
- 约束
- 资源
- 关键事实（标记 observed/estimated/assumed）

**输出模板**：
```markdown
## 先把现状说清楚

- **目标**：[用户目标]
- **阶段**：[当前阶段]
- **约束**：[硬约束列表]
- **资源**：[可用资源]
- **关键事实**：
  - [事实1] (observed)
  - [事实2] (estimated)
  - [事实3] (assumed)
```

---

### 3. 现状够不够清楚

**章节 ID**: `clarity_assessment`

**用户友好标题**: `现状够不够清楚`

**必含内容**：
- 清晰度评分（0-100）
- 清晰度等级（insufficient/workable/clear）
- 是否可以开始诊断
- 缺失的关键信息
- 追问问题（如果需要）

**输出模板**：
```markdown
## 现状够不够清楚

**清晰度评分**：[X]/100

**清晰度等级**：insufficient / workable / clear

**是否可以诊断**：是/否

**缺失信息**：
- [缺失维度1]
- [缺失维度2]

**追问问题**：
1. [问题1]
2. [问题2]
```

### 4. 判断过程

**章节 ID**: `decision_process`

**用户友好标题**: `判断过程`

**必含内容**：
- 至少 3 个候选方案对比
- 评分依据
- 为什么不是其他选项

**输出模板**：
```markdown
## 判断过程

### 候选方案对比

| 候选 | 目标影响 | 杠杆效应 | 阶段匹配 | 资源约束 | 总分 |
|-----|---------|---------|---------|---------|-----|
| [方案A] | [分数] | [分数] | [分数] | [分数] | [总分] |
| [方案B] | [分数] | [分数] | [分数] | [分数] | [总分] |
| [方案C] | [分数] | [分数] | [分数] | [分数] | [总分] |

### 为什么是 [方案A]

[核心理由]

### 为什么不是其他选项

- **不是 [方案B]**：[原因]
- **不是 [方案C]**：[原因]
```

### 6. 资源分配建议

**章节 ID**: `resource_allocation`

**用户友好标题**: `时间、精力、资源应该怎么重新分配`

**必含内容**：
- 主攻线：50%-70%
- 次要线：10%-25%
- 监控线：10%-20%
- 具体分配建议

**输出模板**：
```markdown
## 时间、精力、资源应该怎么重新分配

**分配原则**：清晰时果断倾斜

| 分配桶 | 份额 | 含义 |
|-------|-----|------|
| 主攻主要矛盾 | 50%-70% | 高杠杆时间、注意力投入主线 |
| 压缩次要矛盾 | 10%-25% | 仅保持止损行动 |
| 证据与监控 | 10%-20% | 收集证据、监控触发器 |

**具体建议**：
- **应该增加**：[活动列表]
- **应该减少**：[活动列表]
- **应该保护**：[底线活动]
```

### 7. 接下来怎么做

**章节 ID**: `actions`

**用户友好标题**: `接下来怎么做`

**必含内容**：
- 1-3 个突破行动
- 每个行动的负责人、期限、资源、验收标准
- 每个行动说明改变什么

**输出模板**：
```markdown
## 接下来怎么做

### 行动 1：[行动名称]

- **负责人**：[姓名/角色]
- **期限**：[日期]
- **资源**：[所需资源]
- **验收标准**：[可量化标准]
- **改变什么**：[说明改变主要矛盾的哪一侧]

### 行动 2：[行动名称]

[同上格式]

### 应该停止或推迟的事

- [活动1]：[推迟原因]
- [活动2]：[推迟原因]
```

## 做完以后可能怎样

| 场景 | 概率 | 说明 |
|-----|-----|------|
| 维持现状 | [X]% | [说明] |
| 推荐执行 | [X]% | [说明] |
| 高质量执行 | [X]% | [说明] |
| 执行受阻 | [X]% | [说明] |

### 敏感假设

- **[假设1]**：如果变化，概率会 [上升/下降] [X]%
- **[假设2]**：如果变化，概率会 [上升/下降] [X]%

### 改变判断的证据

- 如果观察到 [证据1]，说明 [判断变化]
- 如果观察到 [证据2]，说明 [判断变化]

### 10. 注意事项

**章节 ID**: `caveats`

**用户友好标题**: `注意事项`

**必含内容**：
- 专业边界警告（如果涉及高风险）
- 不确定性声明
- 假设依赖说明

**输出模板**：
```markdown

- [假设1]：[如果假设错误的影响]
- [假设2]：[如果假设错误的影响]

### 声明

本报告为决策支持工具，不构成最终决策建议。
```

## 事实标记规范

### 标记类型

| 标记 | 含义 | 使用场景 |
|-----|------|---------|
| `(observed)` | 已观察到的事实 | 有数据、记录、证据支撑 |
| `(estimated)` | 估计值 | 基于部分数据和专业判断 |
| `(assumed)` | 假设值 | 基于类比、常识、推测 |

### 使用示例

```markdown
**关键事实**：
- 月活用户 120 万 (observed)
- 转化率约 3.5% (estimated)
- 竞品预算是我们的 2 倍 (assumed)
```

## 语言规范

### 用户友好标题映射

| 概念术语 | 用户友好标题 |
|---------|------------|
| 主要矛盾 | 最关键的卡点 |
| 次要矛盾 | 先不主攻，但要盯住 |
| 矛盾主要方面 | 现在最影响局面的一侧 |
| 因果链 | 为什么这样做会有效 |
| 概率推演 | 做完以后可能怎样 |
| 监控阈值 | 什么时候回头看 |
| 内因 | 你能直接改变的 |
| 外因 | 你只能影响或等待的 |

### 禁止事项

- ❌ 使用纯学术术语不加翻译
- ❌ 结论在后，推理在前
- ❌ 不标记事实来源
- ❌ 行动不说明改变什么
- ❌ 使用装饰性图表

## 模式特定要求

### Fast Scan 模式

**精简版**：
- 先看结论
- 核心理由（2-3 点）
- 主要风险
- 下一步行动

### Decision BRD 模式

**完整版**：所有 10 个必选章节

### Strategy Design 模式

**重点章节**：
- 先看结论
- 推荐方案（含玩法组合）
- 实施路径
- 关键指标

### Case Match 模式

**重点章节**：
- 匹配案例列表
- 各案例核心策略
- 可复制要点
- 注意事项
