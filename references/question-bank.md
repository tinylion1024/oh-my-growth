# Question Bank

结构化追问问题库，按决策模式分类。

## 核心原则

**先追问后判断**：不在信息不足时下结论

**追问策略**：
- 信息不足时，最多问 3 个关键问题
- 信息基本够用时，问剩余缺失问题
- 信息充足时，确认现状快照后深入诊断

---

## 快速扫描模式（Fast Scan）

**适用场景**：初步想法、快速判断、证据不足

**核心 3 问**：

### Q1: 目标锁定

```
你希望这个问题在什么期限内变成什么状态？怎样算解决？
```

**追问点**：
- 具体目标是什么？
- 期限是多久？
- 成功的标准是什么？

### Q2: 稀缺资源

```
现在最稀缺的是时间、人、钱、权限、注意力、信任，还是数据？
```

**追问点**：
- 哪种资源最限制进展？
- 这种稀缺是暂时的还是长期的？
- 有没有办法增加或替代？

### Q3: 单问题测试

```
如果接下来 30 天只能解决一个问题，解决哪个会带来最大变化？
```

**追问点**：
- 为什么是这个问题？
- 解决它后，其他问题会怎样？
- 有什么证据支持这个判断？

## 战略设计模式（Strategy Design）

**适用场景**：需要具体增长策略和玩法组合

**核心 5 问**：

### Q1: 阶段识别

```
这是启动期、验证期、增长期、修复期、转型期，还是恢复期的问题？
```

**阶段特征**：
- 启动期：从 0 到 1，验证需求
- 验证期：验证商业模式可行性
- 增长期：规模化复制和扩张
- 修复期：解决增长带来的问题
- 转型期：寻找新增长曲线
- 恢复期：从危机或衰退中恢复

### Q2: 事实与解释分离

```
哪些是已经发生、别人也能确认的事实？哪些是你的解释、担心或推测？
```

**区分标准**：
- 事实：可观察、可验证、可量化
- 解释：对事实的解读和归因
- 担心：对未来可能性的忧虑
- 推测：基于不完整信息的推断

### Q3: 内外因分离

```
哪些因素你能直接改变？哪些只能影响、规避或等待？
```

**分类**：
- 可直接改变：内部结构、流程、能力、资源分配
- 只能影响：用户行为、合作伙伴、供应商
- 只能规避：竞争对手、市场趋势
- 只能等待：政策变化、技术成熟

### Q4: 重复模式

```
类似问题出现过几次？通常在什么节点爆发？之前尝试过什么，结果如何？
```

**追问点**：
- 问题出现的频率和周期
- 触发条件或节点
- 之前尝试的方案
- 失败或成功的原因

### Q5: 相关方冲突

```
涉及哪些人或组织？每个人最在意的结果分别是什么？
```

**分析维度**：
- 利益相关方列表
- 各方核心诉求
- 潜在利益冲突
- 谁有决策权

## 决策 BRD 模式（Decision BRD）

**适用场景**：需要预算/资源/人力的正式决策

**核心 7 问**：

### Q1: 目标与成功标准

```
你希望这个问题在什么期限内变成什么状态？怎样算解决？
```

**必答要素**：
- 目标状态描述
- 时间期限
- 可量化的成功指标
- 验收标准

### Q2: 当前阶段

```
这件事现在处在什么阶段？
```

**阶段选项**：
- 启动期：从 0 到 1
- 验证期：验证假设
- 增长期：规模化
- 修复期：解决问题
- 转型期：寻找新曲线
- 恢复期：从危机恢复

### Q3: 稀缺资源

```
你现在最稀缺的资源是什么？
```

**资源类型**：
- 时间：截止日期紧迫
- 人：关键人才不足
- 钱：预算有限
- 权限：决策权受限
- 注意力：焦点分散
- 信任：信任资本不足
- 数据：信息缺失

### Q4: 硬约束

```
有哪些不能突破的边界？
```

**约束类型**：
- 法律边界
- 健康边界
- 安全边界
- 伦理边界
- 现金流边界
- 关系边界
- 承诺边界

### Q5: 已尝试动作

```
之前尝试过什么？结果如何？
```

**追问点**：
- 尝试了哪些方案
- 投入了什么资源
- 结果是什么
- 为什么没成功（如果失败）

### Q6: 相关方利益

```
涉及哪些人或组织？他们各自最在意的结果和约束是什么？
```

**分析框架**：
- 决策者：谁拍板
- 执行者：谁干活
- 受益者：谁得到好处
- 受损者：谁承担成本
- 监督者：谁审核

### Q7: 复盘条件

```
什么信号出现时，说明主要矛盾已经转移？
```

**复盘触发**：
- 关键指标达到阈值
- 时间节点到达
- 外部条件变化
- 新问题出现

## 上游诊断问题

**适用场景**：从症状上升到根因

### Q1: 共同原因

```
这些看得见的问题背后，有没有一个共同原因？如果它变了，哪些问题会一起变轻？
```

**分析目的**：识别上游约束

### Q2: 单变量测试

```
如果当前阶段只能改变一个变量，哪一个会让多个可见问题更容易？
```

**分析目的**：找到杠杆点

### Q3: 人才密度测试

```
现在是不是少数优秀的人在救火？如果多 2-3 个同等级或更强的人进来，哪些问题会自然缓解？
```

**分析目的**：判断是否是能力问题

### Q4: 领导者杠杆

```
作为负责人，你现在最应该亲自做的是：交付细节、流程补洞、招人借力、客户边界、还是授权训练？
```

**分析目的**：识别最高杠杆工作

### Q5: 流程 vs 能力

```
这主要是流程问题，还是让流程失败的能力/人才/系统生成问题？
```

**分析目的**：区分表层和根因

### Q6: 隐形约束

```
有什么问题大家不常说，但它决定了这些表面问题反复出现？
```

**提示**：人才密度、权限、信任、现金、注意力、客户边界

### Q7: 时间分配

```
你或团队现在的时间大概花在哪几类事情上？如果粗略分 100%，各占多少？
```

**分析目的**：识别资源错配

### Q8: 注意力分配

```
你作为负责人最常被什么事情拉走注意力？这些事情和真正能改变局面的事情一致吗？
```

**分析目的**：识别注意力错配

## 次要矛盾识别问题

**适用场景**：区分主要矛盾和次要矛盾

### Q1: 次要矛盾测试

```
哪些问题很烦，但即使解决也不能明显改变目标结果？
```

**判断标准**：
- 解决它不会移动目标指标
- 它只是局部痛点
- 它属于后续阶段

### Q2: 推迟理由

```
为什么这个问题可以先不主攻？
```

**推迟理由**：
- 低杠杆：解决它不改变目标
- 低控制：现在无法直接改变
- 高消耗：会占用稀缺资源
- 可替代：有简单 workaround
- 错阶段：属于后续阶段

### Q3: 监控触发

```
什么信号出现时，说明这个问题需要升级处理？
```

**触发条件**：
- 指标恶化超过阈值
- 连续 N 周期无改善
- 引发连锁问题

## 使用指南

### 问题选择策略

| 信息量 | 问题数量 | 问题来源 |
|-------|---------|---------|
| 很少 | 3 | 快速扫描模式 |
| 中等 | 5 | 战略设计模式 |
| 较多 | 7 | 决策 BRD 模式 |
| 症状多根因不明 | 4-8 | 上游诊断问题 |

### 追问优先级

1. 目标与成功标准（必问）
2. 事实与证据（必问）
3. 稀缺资源（必问）
4. 硬约束（必问）
5. 阶段（高优先）
6. 相关方（中优先）
7. 重复模式（中优先）

### 禁止事项

- ❌ 一次性问超过 5 个问题
- ❌ 问用户填长模板
- ❌ 问已经明确的信息
- ❌ 问与决策无关的细节
