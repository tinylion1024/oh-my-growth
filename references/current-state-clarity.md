# Current State Clarity

现状清晰度门控机制，避免信息不足时盲目诊断。

## 核心原则

**先追问后判断**：不在信息不足时下结论

**门控逻辑**：
- 信息不足 → 停止诊断，追问关键问题
- 信息基本够用 → 临时判断，问剩余问题
- 信息充足 → 深入诊断，输出完整报告

---

## 评估维度

| 维度 | 权重 | 什么算清楚 | 评分标准 |
| --- | ---: | --- | --- |
| 目标和成功标准 | 20 | 用户说明了应该变成什么状态、期限、怎样算成功 | 完整=20, 部分=14, 提及=8, 缺失=0 |
| 事实和证据 | 20 | 至少 2 个具体的观察或估计事实，不只是解释 | ≥3个=20, 2个=16, 1个=9, 仅解释=4, 缺失=0 |
| 阶段 | 12 | 当前阶段已命名：启动、验证、增长、修复、转型、恢复等 | 明确=12, 缺失=0 |
| 稀缺资源 | 12 | 时间、人、现金、权限、注意力、信任、数据、精力约束已明确 | 明确=12, 缺失=0 |
| 硬约束 | 12 | 法律、健康、安全、伦理、现金、关系、承诺边界已明确 | 明确=12, 缺失=0 |
| 相关方 | 8 | 相关人员或组织及其利益已可见 | 明确=8, 缺失=0 |
| 重复模式 | 8 | 用户说明了重复出现、触发点、之前尝试、缺失证据 | 明确=8, 缺失=0 |

**总分范围**：0-100

---

## 门控阈值

### insufficient (0-54)

**含义**：信息严重不足，无法负责任地诊断

**行动**：
1. ❌ 不输出主要结论
2. ✅ 输出现状快照
3. ✅ 提出最多 3 个关键问题
4. ✅ 承诺收到回答后继续

**输出模板**：
```markdown
## 现状清晰度

**评分**：[X]/100
**等级**：insufficient（信息不足）

我先把你这件事当成"[初步理解]"看。要判断关键问题，我需要先知道：

1. [关键问题1]
2. [关键问题2]
3. [关键问题3]

回答这些问题后，我会给出具体建议。
```

### workable (55-74)

**含义**：信息基本够用，可以给临时判断

**行动**：
1. ✅ 输出临时判断（标记为临时）
2. ✅ 输出现状快照
3. ✅ 提出剩余问题
4. ✅ 说明缺失信息的影响

**输出模板**：
```markdown
## 现状清晰度

**评分**：[X]/100
**等级**：workable（基本够用）

**临时判断**（等待更多证据后可调整）：

[临时判断内容]

**仍需确认**：
1. [问题1]
2. [问题2]

**缺失信息的影响**：
- 如果 [信息1] 是 [情况A]，建议会调整为 [调整1]
- 如果 [信息2] 是 [情况B]，建议会调整为 [调整2]
```

### clear (75-100)

**含义**：信息充足，可以深入诊断

**行动**：
1. ✅ 重述现状快照
2. ✅ 请用户确认或修正
3. ✅ 深入诊断
4. ✅ 输出完整报告

**输出模板**：
```markdown
## 现状清晰度

**评分**：[X]/100
**等级**：clear（信息充足）

我先复述一下我理解的现状，看看有没有偏差：

- **目标**：[目标]
- **期限/成功标准**：[期限] / [标准]
- **阶段**：[阶段]
- **已发生事实**：[事实列表]
- **最稀缺资源**：[资源]
- **不可突破约束**：[约束]
- **相关方**：[相关方]
- **反复出现的模式/已尝试动作**：[模式]

如果这版现状准确，我再进入深入诊断；如果不准确，你先改这一版。
```

---

## 硬性要求

诊断前必须满足以下条件：

### 必须有

| 维度 | 要求 | 原因 |
|-----|------|------|
| 目标 | 带期限或成功指标 | 没有目标无法判断优先级 |
| 事实 | 至少 2 个具体事实 (observed 或 estimated) | 没有事实无法验证假设 |
| 稀缺资源 | 已明确 | 资源决定可行性 |
| 硬约束 | 已明确 | 约束决定边界 |

### 如果缺失

如果任一硬性要求缺失，**正确的输出是**：

```markdown
## 无法诊断

要负责任地给出建议，我需要先确认：

**必须知道**：
- [ ] [硬性要求1]：[原因]
- [ ] [硬性要求2]：[原因]

**请回答**：
1. [问题1]
2. [问题2]
```

## 追问策略

### 问题优先级

按以下顺序追问：

1. **目标与成功标准**（权重 20）
   - 你希望这个问题在什么期限内变成什么状态？
   - 怎样算解决？

2. **事实与证据**（权重 20）
   - 哪些是已经发生、别人也能确认的事实？
   - 哪些只是你的解释、担心或推测？

3. **稀缺资源**（权重 12）
   - 现在最稀缺的是时间、人、钱、权限、注意力、信任，还是数据？

4. **硬约束**（权重 12）
   - 有哪些不能突破的边界？

5. **阶段**（权重 12）
   - 这是启动期、验证期、增长期、修复期、转型期，还是恢复期？

6. **相关方**（权重 8）
   - 涉及哪些人或组织？他们各自最在意什么？

7. **重复模式**（权重 8）
   - 类似问题出现过几次？通常在什么节点爆发？

### 问题数量限制

| 清晰度等级 | 问题数量 |
|-----------|---------|
| insufficient | 最多 3 个 |
| workable | 最多 5 个 |
| clear | 0 个（确认即可） |

### 禁止事项

- ❌ 一次性问超过 5 个问题
- ❌ 问用户填长模板
- ❌ 问已经明确的信息
- ❌ 问与决策无关的细节

## 评分算法

### 伪代码

```python
def assess_clarity(input):
    scores = {}
    
    # 目标与成功标准 (20)
    if has_goal_and_deadline(input):
        scores['goal'] = 20
    elif has_goal(input):
        scores['goal'] = 14
    elif has_deadline_or_metric(input):
        scores['goal'] = 8
    else:
        scores['goal'] = 0
    
    # 事实与证据 (20)
    strong_facts = count_facts(input, types=['observed', 'estimated'])
    if strong_facts >= 3:
        scores['facts'] = 20
    elif strong_facts == 2:
        scores['facts'] = 16
    elif strong_facts == 1:
        scores['facts'] = 9
    elif has_any_facts(input):
        scores['facts'] = 4
    else:
        scores['facts'] = 0
    
    # 其他维度 (12/12/12/8/8)
    scores['stage'] = 12 if has_stage(input) else 0
    scores['resources'] = 12 if has_resources(input) else 0
    scores['constraints'] = 12 if has_constraints(input) else 0
    scores['stakeholders'] = 8 if has_stakeholders(input) else 0
    scores['patterns'] = 8 if has_patterns(input) else 0
    
    # 总分
    total = sum(scores.values())
    
    # 等级
    if total < 55:
        level = 'insufficient'
    elif total < 75:
        level = 'workable'
    else:
        level = 'clear'
    
    return {
        'score': total,
        'level': level,
        'scores': scores,
        'missing': find_missing(scores),
        'questions': select_questions(missing, level)
    }
```

## 集成方式

### 在 Lead Agent 中使用

```yaml
clarity_gate:
  reference: "references/current-state-clarity.md"
  
  workflow:
    1. 评估用户输入
    2. 计算清晰度评分
    3. 判断清晰度等级
    4. 根据等级选择行动
    5. 如果 insufficient，追问并停止
    6. 如果 workable，临时判断并追问
    7. 如果 clear，深入诊断
```

### 在 Guide Agent 中使用

```yaml
follow_up:
  reference: "references/current-state-clarity.md"
  
  strategy:
    - 识别缺失维度
    - 按优先级选择问题
    - 限制问题数量
    - 输出追问
```

## 示例

### 示例 1：信息不足

**用户输入**：
```
我想提升用户增长。
```

**评估结果**：
- 目标：提及（8 分）
- 事实：缺失（0 分）
- 阶段：缺失（0 分）
- 资源：缺失（0 分）
- 约束：缺失（0 分）
- 相关方：缺失（0 分）
- 模式：缺失（0 分）

**总分**：8/100
**等级**：insufficient

**输出**：
```markdown
## 现状清晰度

**评分**：8/100
**等级**：insufficient（信息不足）

要判断增长策略，我需要先知道：

1. 你希望多长时间内达到什么增长目标？怎样算成功？
2. 现在最稀缺的是用户来源、转化能力、还是留存能力？
3. 当前处于什么阶段：验证期、增长期、还是修复期？

回答这些问题后，我会给出具体建议。
```

### 示例 2：信息基本够用

**用户输入**：
```
我们是 SaaS 产品，月活 10 万，想在未来 3 个月把付费转化率从 3% 提升到 5%。
团队 5 人，预算有限。之前试过邮件营销，效果不好。
```

**评估结果**：
- 目标：完整（20 分）
- 事实：2 个（16 分）- 月活 10 万、转化率 3%
- 阶段：缺失（0 分）
- 资源：明确（12 分）- 团队 5 人、预算有限
- 约束：缺失（0 分）
- 相关方：缺失（0 分）
- 模式：明确（8 分）- 试过邮件营销

**总分**：56/100
**等级**：workable

**输出**：
```markdown
## 现状清晰度

**评分**：56/100
**等级**：workable（基本够用）

**临时判断**：

基于 SaaS 产品、月活 10 万、转化率 3%，提升到 5% 的目标：
- 核心问题可能在：价值感知、定价策略、或激活流程
- 邮件营销效果不好，可能因为触达时机或内容不匹配
- 建议：先诊断转化漏斗，找到最大流失点

**仍需确认**：
1. 当前处于什么阶段：验证期、增长期、还是修复期？
2. 有哪些不能突破的约束（如定价不能变）？

**缺失信息的影响**：
- 如果是验证期，建议优先产品迭代
- 如果定价不能变，建议优先价值感知优化
```

### 示例 3：信息充足

**用户输入**：
```
我们是 B2B SaaS，处于增长期，ARR 500 万。
目标是 6 个月内 ARR 翻倍到 1000 万。
团队 20 人，销售 5 人，产品 8 人，其他 7 人。
最稀缺的是销售线索，每月只有 50 个合格线索。
约束：不能增加销售人头，预算可增加 20%。
之前试过内容营销，每月产生 10 个线索，但质量不稳定。
竞品预算是我们的 3 倍。
```

**评估结果**：
- 目标：完整（20 分）
- 事实：≥3 个（20 分）- ARR、线索数、竞品预算
- 阶段：明确（12 分）- 增长期
- 资源：明确（12 分）- 团队 20 人、预算可增 20%
- 约束：明确（12 分）- 不能增加销售人头
- 相关方：部分（8 分）- 销售、产品团队
- 模式：明确（8 分）- 内容营销尝试

**总分**：92/100
**等级**：clear

**输出**：
```markdown
## 现状清晰度

**评分**：92/100
**等级**：clear（信息充足）

我先复述一下我理解的现状，看看有没有偏差：

- **目标**：6 个月内 ARR 从 500 万翻倍到 1000 万
- **期限/成功标准**：6 个月 / ARR 1000 万
- **阶段**：增长期
- **已发生事实**：
  - 当前 ARR 500 万 (observed)
  - 每月 50 个合格线索 (observed)
  - 内容营销每月 10 个线索 (observed)
  - 竞品预算是我们的 3 倍 (estimated)
- **最稀缺资源**：销售线索
- **不可突破约束**：不能增加销售人头
- **相关方**：销售团队 5 人、产品团队 8 人
- **反复出现的模式/已尝试动作**：内容营销尝试，质量不稳定

如果这版现状准确，我再进入深入诊断；如果不准确，你先改这一版。
```
