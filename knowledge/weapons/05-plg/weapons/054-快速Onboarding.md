# 54. 快速Onboarding

> 快速激活

## 玩法定位

- 所属模块：[产品驱动增长](<../01-overview.md>)
- 适用阶段：适合 SaaS、工具、协作产品，也适合做规模化转化优化
- 核心目标：让产品体验本身承担获客、激活、留存和传播的一部分职责
- 难度 / 影响 / 证据：Medium / High / B级

## 核心讲解

快速Onboarding 是“产品驱动增长”模块中的典型玩法，通常用来 让产品体验本身承担获客、激活、留存和传播的一部分职责。它的价值不在于单个动作本身，而在于 用低摩擦体验、自然传播触点和清晰的价值时刻，把增长动作嵌进产品本身。

如果只把它理解成“快速激活”，很容易停留在表层执行；真正要做的是把触发时机、用户动机、执行摩擦和回收指标设计成一条闭环。

在这个玩法里，最重要的策略定位是：快速让用户感受到产品价值。

## 关键要点

- 快速Onboarding 的核心不是“多做一个动作”，而是 快速让用户感受到产品价值。
- Onboarding完成率
- 激活率
- Time to Value
- 判断是否值得持续投入，要回到 让产品体验本身承担获客、激活、留存和传播的一部分职责 这个目标，而不是只看表面热度。

## 深入讲解

### 战术
快速让用户感受到产品价值

### Onboarding设计
1. 欢迎+价值承诺
2. 3步快速上手
3. 第一个成果展示
4. 成就感庆祝

### 关键要素
- 不要让用户迷茫
- 每步都有反馈
- 快速到"aha moment"
- 可以跳过

### 案例
- Notion：3步创建第一个workspace
- Slack：邀请团队快速聊天
- Linear：导入项目快速上手

### 关键指标
- Onboarding完成率
- 激活率
- Time to Value

## 执行要点

1. 先确认这次动作要解决的核心问题是否真的是“让产品体验本身承担获客、激活、留存和传播的一部分职责”。
2. 把触发场景、执行动作和用户回流路径设计成一条最短闭环。
3. 先用小范围实验验证，再决定是否加预算、加人力或做产品化投入。

## 适用判断

### 优先使用

- 用户可以在很短时间内体验到核心价值。
- 产品本身有天然的协作、分享或升级路径。
- 你想减少对销售或投放的强依赖。

### 暂不优先

- 产品价值必须依赖长交付、重实施或强人工服务才能体现。
- 团队无法做埋点、实验和产品迭代，PLG 会停留在口号层。
- 用户体验本身还不稳定，过早放大流量只会放大流失。
