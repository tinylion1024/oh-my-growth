# Growth Master 用户指南

## 快速开始

### 安装

```bash
# 复制到Claude技能目录
cp -R growth-master ~/.claude/skills/

# 安装Agent模板到项目
./scripts/install.sh /path/to/project
```

### 基本使用

```
/omg-diagnose [问题描述]
/omg-assess [问题描述]
/omg-design [问题描述]
/omg-match [问题描述]
/omg-learn [问题描述]
```

完整命令与场景入口请参见项目 [README](../README_CN.md#命令参考)。

## 核心模式详解

### 1. Assess（评估模式）

**用途**：快速评估增长机会是否可行

**适用场景**：
- 有一个初步想法，不确定是否值得投入
- 需要快速决策
- 证据不足时的初步判断

**输出**：
- 一句话建议
- 核心理由（2-3点）
- 主要风险
- 下一步行动

**示例**：
```
/omg-assess

我们是一个SaaS协作工具，有5000注册用户，月活800。
想通过邀请裂变增长，预算有限。
请评估这个方向是否可行。
```

---

### 2. Design（设计模式）

**用途**：设计具体的增长策略和玩法组合

**适用场景**：
- 明确了问题方向
- 需要具体方案
- 想知道用什么玩法组合

**输出**：
- 策略方向
- 推荐玩法组合
- 成功案例参考
- 实施路径
- 关键指标

**示例**：
```
/omg-design

我们是电商平台，日活10万，首购后流失率60%。
请设计留存增长策略。
```

---

### 3. Learn（学习模式）

**用途**：系统学习增长知识

**适用场景**：
- 想了解增长方法论
- 系统性学习某个领域
- 获取学习资源推荐

**输出**：
- 推荐学习模块
- 相关理论流派
- 案例+玩法组合
- 进阶路径

**示例**：
```
/omg-learn

我想系统学习SaaS增长，目前是入门水平。
```

---

### 4. 方案复核（使用 Assess）

**用途**：评估现有方案，识别风险和改进空间

**适用场景**：
- 已有方案，需要第三方视角
- 识别潜在风险
- 验证假设

**输出**：
- 方案评估
- 风险识别
- 假设质疑
- 改进建议

**示例**：
```
/omg-assess

我们计划投入50万做裂变活动，预期增长2万用户。
方案：邀请奖励50元，双方各得。
```

---

### 5. Match（匹配模式）

**用途**：匹配相似成功案例

**适用场景**：
- 寻找参考案例
- 学习成功经验
- 验证思路

**输出**：
- 匹配案例列表
- 各案例核心策略
- 可复制要点
- 注意事项

**示例**：
```
/omg-match

我们是AI教育产品，想通过游戏化提升学习完成率。
```

## Agent体系说明

Growth Master 使用多Agent协作进行分析：

### 核心Agent

| Agent | 职责 |
|-------|------|
| Lead Agent | 编排协调、问题分类 |
| Growth Agent | 增长机制可行性 |
| Monetization Agent | 变现影响评估 |
| ROI Agent | 投资回报计算 |
| Execution Agent | 执行可行性 |
| Skeptic Agent | 风险识别、假设挑战 |
| Narrative Agent | 最终文档撰写 |

### 知识Agent

| Agent | 职责 |
|-------|------|
| Case Agent | 案例匹配 |
| Weapon Agent | 玩法推荐 |
| Theory Agent | 理论支撑 |

## 置信度说明

每个输出都标注置信度：

| 置信度 | 含义 | 建议 |
|--------|------|------|
| High | 强证据、可测试、执行可控 | 可直接决策 |
| Medium | 可行机制但有重要假设 | 推荐小实验验证 |
| Low | 证据稀少、重大未知 | 转化为学习/研究 |

## 证据分级说明

知识库中的案例、玩法、理论都有证据分级：

| 等级 | 含义 | 可信度 |
|------|------|--------|
| A | 元分析、系统综述、官方统计 | 最高 |
| B | 同行评审论文、行业标准 | 高 |
| C | 结构化专家意见、现场证据 | 中 |
| D | LLM建议、类比、常识 | 低 |
| E | 博客、营销文案、社交媒体 | 最低 |

**使用建议**：
- 优先参考 A/B 级证据
- C 级证据需要结合其他来源验证
- D/E 级证据仅作参考，不作为决策依据

## 现状清晰度门控

系统会在决策前评估现状清晰度，避免在信息不足时做出错误决策：

### 7个评估维度

| 维度 | 权重 | 说明 |
|------|------|------|
| 目标与成功标准 | 20% | 目标是否明确、可量化？ |
| 事实与证据 | 20% | 有多少已验证的事实？ |
| 阶段判断 | 12% | 产品/业务阶段是否明确？ |
| 稀缺资源 | 12% | 最稀缺的资源是什么？ |
| 硬约束 | 12% | 有哪些不可逾越的约束？ |
| 利益相关者 | 8% | 关键决策者是谁？ |
| 重复模式 | 8% | 是否有历史经验可参考？ |

### 清晰度等级

| 等级 | 分数范围 | 含义 | 行动 |
|------|----------|------|------|
| 不足 | 0-54 | 无法开始诊断 | 必须先澄清现状 |
| 可用 | 55-74 | 可以开始诊断 | 边做边澄清 |
| 清晰 | 75-100 | 可以深入诊断 | 直接进入分析 |

## 安全边界

系统会自动识别高风险领域并触发警告：

### 风险类型

| 类型 | 触发词示例 | 响应 |
|------|-----------|------|
| 财务风险 | 投资、融资、估值、定价 | 提供框架，建议咨询专业顾问 |
| 法律风险 | 合规、合同、知识产权 | 提供风险清单，建议咨询律师 |
| 监管风险 | 牌照、数据合规、隐私保护 | 提供检查清单，建议咨询专业机构 |
| 运营风险 | 裁员、重大组织变更 | 提供分析框架，建议咨询顾问 |

**当触发安全边界时**：
- 系统会添加警告声明
- 置信度会被限制
- 建议会改为可逆、保守、审查导向

## 常见问题

### Q: 输出结果太长怎么办？

A: 使用 Fast Scan 模式可以获得更简洁的输出：
```
/omg-assess --mode fast
```

### Q: 案例不够相关怎么办？

A: 提供更多上下文信息，或指定行业/阶段：
```
/omg-match

【行业】在线教育
【阶段】1-10
【问题】用户完课率低
```

### Q: 如何获得更精准的分析？

A: 使用 [快速启动模板](../templates/quick-start.md) 提供完整信息。

### Q: 可以只使用某些Agent吗？

A: 可以，在请求中指定：
```
/omg-assess --agents Growth,ROI,Skeptic
```

## 进阶使用

### 自定义Agent权重

```
/omg-assess

【问题】...
【权重】
- Growth Agent: 0.3
- ROI Agent: 0.4
- Skeptic Agent: 0.3
```

### 指定案例参考

```
/omg-design

【问题】...
【参考案例】请参考Dropbox和Slack的增长模式
```

### 输出格式

```
/omg-assess --format brd
--format 可选: fast, brd, strategy
```
