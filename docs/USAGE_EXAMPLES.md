## 核心命令

### diagnose - 策略诊断

**何时使用**：您有一个增长问题，需要快速获得诊断和优先级判断。

#### 场景 1：DAU 下降

```
/omg diagnose 我们的产品 DAU 最近下降了 20%，该怎么办？
```

**典型输出**：

```
┌─────────────────────────────────────────────────────────┐
│  📌 阶段诊断                                             │
├─────────────────────────────────────────────────────────┤
│  增长放大期 · 用户深耕                                   │
│  北极星指标：月活跃用户（MAU）                           │
│  当前约束：留存率下降                                    │
│                                                         │
│  📌 一句话判断                                          │
│  不是获客问题，是流失加剧。先修留存再补获客。            │
│                                                         │
│  📌 核心矛盾                                            │
│  • 流失用户中 60% 集中在注册后 7 天内                   │
│  • 新用户引导流程缺乏价值感知点                          │
│  • 核心功能使用率低于 30%                                │
│                                                         │
│  📌 优先级排序                                          │
│  1. 优化 Onboarding（置信度：High）                     │
│  2. 增加激活触发点（置信度：Medium）                     │
│  3. 新用户礼包（置信度：Low）                            │
│                                                         │
│  📌 建议做 / 不做                                       │
│  ✅ 做：7 天留存提升实验                                 │
│  ❌ 不做：大规模广告投放（放大的是流失）                 │
│                                                         │
│  📌 2 周最小实验                                        │
│  1. 改造注册后首次体验，增加价值感知                     │
│  2. 追踪：D7 留存率、功能使用率                          │
│  3. 停止信号：D7 留存提升 < 5%                          │
│                                                         │
│  📌 相关案例                                            │
│  • [Dropbox: 引导流程优化](../knowledge/cases/dropbox-onboarding.md)
│  • [Notion: 激活机制设计](../knowledge/cases/notion-activation.md)
└─────────────────────────────────────────────────────────┘
```

#### 场景 2：SaaS 产品冷启动

```
/omg diagnose 我们是 B2B SaaS 产品，刚上线，如何获得前 100 个付费客户？
```

**典型输出**：

```
┌─────────────────────────────────────────────────────────┐
│  📌 阶段诊断                                             │
├─────────────────────────────────────────────────────────┤
│  产品验证期 · 用户获取                                   │
│  北极星指标：付费客户数                                  │
│  当前约束：缺乏初始信任                                  │
│                                                         │
│  📌 一句话判断                                          │
│  还没到增长阶段，先完成 PMF 验证。                       │
│                                                         │
│  📌 核心矛盾                                            │
│  • 产品价值未被验证                                      │
│  • 没有标杆客户背书                                      │
│  • 目标用户画像不清晰                                    │
│                                                         │
│  📌 优先级排序                                          │
│  1. Founder 销售（置信度：High）                        │
│  2. 行业社群渗透（置信度：Medium）                       │
│  3. 内容营销（置信度：Low - 见效慢）                    │
│                                                         │
│  📌 建议做 / 不做                                       │
│  ✅ 做：创始人亲自做前 10 个客户                         │
│  ✅ 做：找到 1-2 个标杆客户深度合作                      │
│  ❌ 不做：付费广告（ROI 极低）                           │
│  ❌ 不做：大规模推广（产品会暴露问题）                   │
│                                                         │
│  📌 2 周最小实验                                        │
│  1. 列出 50 个目标客户，创始人直接 BD                    │
│  2. 追踪：触达数、回复率、转化率                         │
│  3. 成功信号：获得 3 个付费客户                          │
│  4. 停止信号：触达 50 个仍无转化                         │
└─────────────────────────────────────────────────────────┘
```

### assess - 机会评估

**何时使用**：有一个想法，不确定是否值得深入分析。

#### 场景 1：评估裂变可行性

```
/omg assess 我们准备做裂变活动，先评估一下可行性
```

**典型输出**：

```
┌─────────────────────────────────────────────────────────┐
│  📌 清晰度评估                                           │
├─────────────────────────────────────────────────────────┤
│  当前信息清晰度：54/100（不足）                          │
│                                                         │
│  ⚠️ 缺失的关键信息：                                    │
│  1. 产品当前 DAU 和留存率？                             │
│  2. 用户自发分享率是多少？                               │
│  3. 产品是否有明确的价值感知点？                         │
│                                                         │
│  📌 初步可行性判断                                      │
│  当前状态：信息不足，无法判断                            │
│                                                         │
│  📌 建议下一步                                          │
│  1. 先回答上述问题                                       │
│  2. 运行 `/omg diagnose` 完成诊断                        │
│  或                                                      │
│  3. 运行 `/omg diagnose 我们是 xx 产品，DAU xx，想...`  │
└─────────────────────────────────────────────────────────┘
```

#### 场景 2：评估信息充分

```
/omg assess 我们是教育类 APP，DAU 50万，次日留存 45%，
用户自发分享率 3%，想通过邀请奖励提升获客
```

**典型输出**：

```
┌─────────────────────────────────────────────────────────┐
│  📌 清晰度评估                                           │
├─────────────────────────────────────────────────────────┤
│  当前信息清晰度：78/100（清晰）                          │
│                                                         │
│  ✅ 关键信息已具备                                      │
│  • 产品阶段：增长放大期                                  │
│  • 当前指标：DAU 50万，留存 45%                         │
│  • 基础：自发分享率 3%（有分享基础）                    │
│                                                         │
│  📌 可行性判断                                          │
│  综合评分：72/100（建议进入详细分析）                    │
│                                                         │
│  有利因素：                                              │
│  • 留存率健康，裂变不会放大流失                          │
│  • 已有 3% 自发分享基础                                  │
│  • 教育场景适合社交传播                                  │
│                                                         │
│  风险因素：                                              │
│  • 邀请奖励可能吸引低质量用户                            │
│  • 需要设计防刷机制                                      │
│                                                         │
│  📌 建议下一步                                          │
│  运行 `/omg design 设计裂变增长策略` 获取具体方案        │
└─────────────────────────────────────────────────────────┘
```

### fast-scan - 快速扫描

**何时使用**：有一个想法，想快速判断是否靠谱。

#### 场景：评估新渠道

```
/omg fast-scan TikTok 广告适合我们的 B2B SaaS 产品吗？
```

**典型输出**：

```
┌─────────────────────────────────────────────────────────┐
│  📌 快速扫描：TikTok 广告 × B2B SaaS                     │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  📌 一句话判断                                          │
│  ❌ 不推荐。渠道属性与目标用户不匹配。                   │
│                                                         │
│  📌 核心分析                                            │
│  匹配度：低                                              │
│  • TikTok 用户：年轻、娱乐导向                          │
│  • B2B SaaS 用户：决策者、工作场景                      │
│  • 渠道属性：冲动消费、短视频                            │
│  • 产品属性：理性决策、长周期                            │
│                                                         │
│  📌 替代建议                                            │
│  考虑以下渠道：                                          │
│  • LinkedIn Ads（决策者聚集）                           │
│  • Google Search Ads（需求明确）                        │
│  • 行业媒体/社群（精准触达）                            │
│                                                         │
│  📌 如果一定要测试                                      │
│  1. 预算控制在 $500 以内                                │
│  2. 目标：品牌曝光而非直接转化                           │
│  3. 内容：偏品牌故事，而非功能介绍                       │
└─────────────────────────────────────────────────────────┘
```

## 💡 使用技巧

### 1. 提供足够的上下文

❌ 不好：
```
/omg diagnose 怎么做增长？
```

✅ 好：
```
/omg diagnose 我们是 B2B SaaS 产品，刚上线 3 个月，
DAU 500，付费用户 20 个，获客成本 $50，
想降低获客成本
```

### 2. 先 assess 再 diagnose

当问题描述不够清晰时，先用 `assess` 评估信息是否充分：

```
/omg assess 我们想做大促活动
↓
系统会告诉你缺少什么信息
↓
补充信息后再运行 /omg diagnose
```

### 3. 使用场景快捷入口

对于常见场景，直接使用快捷命令：

```
/omg cold-start ...  # 冷启动问题
/omg retention ...   # 留存问题
/omg monetization ... # 变现问题
/omg referral ...    # 裂变问题
```

### 4. 迭代式提问

```
# 第一轮：快速判断
/omg fast-scan TikTok 广告适合我们吗？

# 第二轮：深入分析
/omg diagnose 如果要做 TikTok，应该怎么做？

# 第三轮：具体方案
/omg design 设计 TikTok 广告投放策略
```
